How well do quantum compilers handle Boolean functions?

A re-run of a bachelor thesis from 2022/23 with current compiler versions and more compilers. Jannik Pflieger.

SummaryBackgroundMethod Results2022 vs. nowDiscussion Reproduce

Summary

Many quantum algorithms take a classical Boolean function as input, in the form of an oracle. Before an oracle can run on hardware, a compiler has to rewrite it as a sequence of one- and two-qubit gates that respects which qubits are physically connected. This project measures how many gates different compilers need for this, for a small set of Boolean functions and four qubit layouts.

The original study (bachelor thesis, Goethe University Frankfurt, 2023) compared Qiskit, tket and pyQuil, and had to leave out Cirq and BQSKit. Here the same experiment is run again with the current versions of those tools, and PennyLane, Qibo and Qrisp are added. Every compiled circuit is simulated to check that it really implements the function.

Main observations

  • Using the structure of the function matters more than the choice of tool. Where a tool recognises the Boolean structure (Qiskit's expression interface for AND, quilc for XOR, Qrisp's logic synthesis), a 10-qubit oracle needs tens to a few hundred two-qubit gates. Treated as a general matrix (Qiskit matrix input, Cirq, PennyLane, Qibo), the count grows roughly as 4n: tens of thousands of gates at 8 to 10 qubits, or a timeout.
  • No compiler is best for all three functions. Among the compilers, the lowest verified counts at 10 qubits on the fully connected layout are 288 two-qubit gates for AND (Qiskit, equal to the textbook construction), 537 for OR (Qiskit) and 9 for XOR (quilc and Qrisp PPRM, optimal).
  • Qiskit improved for AND and OR, but not for XOR. AND at 10 qubits went from 1,532 CNOTs (2022) to 288, OR from 3,731 to 537. XOR went from the optimal 9 CNOTs to 73,728, because the current expression synthesis no longer finds the CNOT-only circuit.
  • tket shows the opposite trend. In 2022 tket had the best AND (288 CNOTs at 10 qubits); now it needs 1,534. OR improved strongly (6 qubits: 2,480 to 94 CNOTs).
  • Cirq and BQSKit, which were excluded in 2022, now work, with limits. Cirq's default path still leaves gates on more than three qubits undecomposed, but an explicit Shannon decomposition works up to 7 or 8 qubits within the time limit. BQSKit finds optimal or near-optimal circuits for 3 qubits, but its numerical synthesis does not finish within 300 s from 4 qubits on (5 for XOR).
  • The correctness check found real errors. Qrisp's Gray-code synthesis returns a wrong XOR circuit from 4 qubits on. quilc stops with numerical errors for some 7 and 8 qubit cases.

Background

Boolean functions as quantum operations

A quantum computer can only apply reversible operations. A Boolean function f: {0,1}n → {0,1} is therefore implemented with one extra output qubit:

|x, y⟩ ↦ |x, y ⊕ f(x)⟩

The inputs stay unchanged and the output qubit is flipped whenever f(x) = 1. As a matrix this is a permutation of the computational basis states, so a function with n inputs becomes a 2n+1 × 2n+1 permutation matrix on n + 1 qubits. Such matrices have a lot of structure, so one would expect compilers to decompose them more efficiently than an arbitrary unitary of the same size.

What a compiler has to do

  1. Synthesis: express the operation in a fixed set of native gates (here: single-qubit rotations and CNOT or CZ).
  2. Mapping and routing: place logical qubits on physical qubits and insert SWAP operations whenever two qubits that must interact are not connected.
  3. Optimisation: remove or merge redundant gates.

Two-qubit gates are the main source of error on current hardware, so their number is the main metric here.

For orientation: AND and OR on 3 qubits (the Toffoli gate) need 6 CNOTs. For more inputs, constructions without extra qubits exist whose CNOT count grows polynomially in n. XOR needs exactly one CNOT per input. A generic method for an arbitrary unitary needs on the order of 4n CNOTs.

Qubit layouts

As in the thesis, four connectivity graphs are used. The grid is the smallest square grid with enough qubits (e.g. 3 × 3 for 5 to 9 qubits), so the compiler may also choose which qubits to use.

Cirq and quilc use CZ instead of CNOT. One CNOT equals one CZ plus single-qubit gates, so two-qubit gate counts are directly comparable. The "textbook construction" is not a compiler. It shows what is possible when the structure of the function is used directly.

Measurements and correctness check

  • Number of two-qubit gates, number of all gates, and the wall-clock time of the compile call.
  • Each job runs in its own process with a limit of 300 seconds. When a size times out, larger sizes of the same series are not attempted.
  • Every result is simulated. Using the initial and final qubit placement reported by the compiler, every basis input is checked to map to the right output with a common phase, i.e. the circuit equals the oracle up to a global phase (infidelity below 10−6; BQSKit synthesises numerically and is therefore approximate). For large circuits a random subset of inputs is checked. Results that fail the check are marked with ✗ and not drawn in the charts.
  • For routed results it is also checked that every two-qubit gate acts on connected qubits.

Discussion

Structure-aware versus generic synthesis

The oracles studied here are permutation matrices with very regular structure: AND and OR are a single multi-controlled X gate (with X gates around it for OR), and XOR is a row of CNOTs. The results show two groups of compilers. Generic unitary synthesis, such as the quantum Shannon decomposition used by Cirq, PennyLane and Qibo and by Qiskit for a UnitaryGate, produces circuits that grow exponentially in the number of qubits. This is independent of how simple the function is. The XOR oracle, which needs only n CNOTs, costs these methods as much as AND or OR.

Compilers or interfaces that look at the function itself are orders of magnitude better, but each one only for some functions. quilc finds the optimal circuit for XOR, but not for AND and OR. Qiskit's BitFlipOracleGate turns a single AND into one multi-controlled X, but expands XOR into a large cascade. Qrisp's PPRM synthesis (positive-polarity Reed–Muller form) is optimal for XOR and good for AND, but weak for OR, whose Reed–Muller form has 2n − 1 terms.

Changes since 2022

Compiler versions changed a lot in four years, and the changes are not monotonic. Qiskit replaced its Tweedledum-based Boolean synthesis, which improved AND and OR but lost the efficient XOR. tket's AND result in 2022 came from a special decomposition for multi-controlled X gates. The current numbers suggest that this special case is no longer used for a ToffoliBox, and AND now costs about five times more at 10 qubits. For anyone who relies on a specific compiler result, this suggests checking gate counts again after upgrades.

Qubit layout

Restricted layouts add SWAP overhead, typically a factor of about 1.5 to 4.5 over the fully connected case for the same compiler. The grid, which offers spare qubits and more connections, is usually between line and fully connected. The ranking of the compilers stays mostly the same across layouts.

Small functions

All compilers recognise that always-0, always-1 and identity need no or one two-qubit gate, with two exceptions: BQSKit returns two CNOTs that cancel for always-0, and Qrisp's Gray synthesis uses two CNOTs for the identity. For the two-of-three (majority) function, Qrisp's Gray synthesis needs 12 CNOTs, fewer than the 18 of the textbook construction with three Toffoli gates; quilc also reaches 18.

Limitations

  • Only a small, symmetric family of functions is tested. Results may differ for random or structured functions.
  • Each compiler is used with one reasonable configuration. Other settings or plugins may give better numbers.
  • No ancilla qubits are given to the compilers, except the spare qubits of the grid layout.
  • Compile times were measured on a shared 4-core cloud machine and are only indicative.
  • Gate counts do not include hardware noise or circuit depth.
  • The Qrisp circuits are translated to the gate set with Qiskit without optimisation, and Qrisp has no routing, so it is only run on the fully connected layout.
  • For Cirq, the matrix is decomposed with cirq.quantum_shannon_decomposition, because the default optimize_for_target_gateset still leaves matrix gates on more than three qubits undecomposed (as in 2022).
